# 信源名单（随技能分发）

## 说明

- 本文件随技能一起发布，**用户安装后即精确生效**，无需任何额外操作。
- 维护方式：直接编辑本文件 → 推送 GitHub → CI 自动 patch 版本号 +1 并发布。**名单变更也是一次版本发布，但不用手动改版本号。**
- 命中本名单的来源按对应类别硬处理；未命中的回落到 `source-credibility.md` 第五节的通用特征判定。
- 用户自己的补充名单在技能目录之外：`~/.bilei/user-blocklist.md`，更新技能不会丢失。两份名单合并执行，用户名单优先级更高。

## A 类 · 禁用（不作任何证据，连线索也不采信）

| 来源 | 域名 | 判定理由 |
|---|---|---|
| 今日头条 | `toutiao.com`（含聚合号、转载号） | 内容农场与聚合搬运为主，原始出处难回溯 |
| 百家号 | `baijiahao.baidu.com` | 洗稿与标题党高发，署名不可核验 |

## B 类 · 限用（2020-01-01 之后内容只作线索，须另找 L2/L3 交叉验证）

| 来源 | 域名 | 处理 |
|---|---|---|
| 什么值得买 | `smzdm.com` | 导购返利；评价层禁用，价格仅作补充线索（历史好价以慢慢买为准） |
| 知乎 | `zhihu.com` | 问答社区软广高发；引用须回查原始出处，否则计 0 源 |
| 微信公众号 | `mp.weixin.qq.com` | 通稿软文比例高；按「转引计 0 源」处理 |

## 例外与边界

- **慢慢买** `manmanbuy.com`：价格事实层可用（价格曲线），不提供品质评价。
- 命中 B 类的来源若直接给出 L1/L2 证据（如贴出官方抽检公告原文、检测报告编号），可采信该 L1/L2 证据本身，但不采信其评价性结论。
- 全网仅有 A/B 类来源在讨论某品类时 → 第一屏写明「该品类缺乏可用信源」，按「目前没有」处理，不凑数推荐。
